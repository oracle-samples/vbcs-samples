Create a Dynamic Table component that displays editable rows of employees including an empty row to add a record for a new employee. Row data is edited in a form layout which is different for add row and for edit row. All changes are stored in a buffer until the user clicks Save, at which time a REST call posts the changes to the backend service.

Create a Dynamic Table

  1. Drag and drop a JET Dynamic Table component from the Component palette on the template in the Page Designer.
  2. In the Quick Start tab of the Properties pane, click Configure Dynamic UI.
  3. In the Configure Dynamic UI dialog that appears, choose the business object or REST endpoint that you want to use as the data source for the form, and click Next.
  4. In the Select Rule Set page of the Configure Dynamic UI dialog, click New Rule Set to define your own display logic, and enter a rule set label and ID, such as dynamicTableFormEdit.
  5. In the Fields section, select the following fields, and click Next, and then click Finish.
    • firstName
    • lastName
    • phoneNumber
    • email
  6. Create a new variable, employeesCustomBDP, of type Buffering Data Provider. Configure its dataProvider required property to be employeesListSDP.

  7. In the Properties pane for the Table component, change the data property to point to [[ $variables.employeesCustomBDP.instance ]] instead of employessListSDP.

    Note the use of instance at the end of the property value.

Make the Dynamic Table Editable

  1. Select the Dynamic Table and, in the All tab of the Properties pane, set the Edit Mode property as managedRowEdit.
  2. In the JSON tab of the Designer, set the default endpoint of businessObjectsGetallEmployeeMetadata to businessObjects/update_Employee and remove "metadata-path":"items", so that the entry is as follows: 
      "metadata": {
    "businessObjectsGetallEmployeeMetadata": {
      "type": "vb/DynamicLayoutMetadataProviderDescriptor",
      "defaultValue": {
        "endpoint": "businessObjects/update_Employee"
      }
    }
  },

    When the Quick Start wizard configures the table, it includes these entries that we need to edit to change the endpoint as update.

Add Row Feature

  1. In the Page Designer, select the Dynamic Table component and, in the All tab of the Properties pane, set the Add Row Display property to top. This adds a new empty row by default on top of the table.

Add a Custom Form Layout for Editing

To enable form-based row editing and creation, a dynamic form layout needs to be created. The Add and Edit flow can share the same form layout or have separate layouts.
  1. To add a custom form layout for adding a new row, navigate to the Rule Sets section of Employee and create a new Rule Set named dynamicTableFormAddRow of component type Dynamic Form.
  2. Select the fields this new layout (for example, firstName, lastName, and salary). Also set the Direction property of the form to Column and the Max Columns property to 3, so that the three fields in the Add Row form layout appear side by side.
  3. Similarly, to add a new custom form layout for editing the existing rows, navigate to the Rule Sets section of Employee and create a new Rule Set named dynamicTableFormEditRow of component type Dynamic Form.
  4. Select the fields for this new layout. Also set the Direction property of the form to Column and the Max Columns property to 3.
  5. To use these Rule Sets, navigate to the JSON tab of the Employee layout. Search for the dynamicTableFormEdit Rule Set and add the custom rule sets for add and edit row as follows.

Add a List of Values (LOV)

Dynamic UI components create their UI using server-side metadata that describes the data model. The more complete the server-side metadata, the more possibilities available to you to create a feature-rich UI with dynamic UI components. If server-side metadata is missing or incomplete, you can enhance it on the client-side. In this step, we show how to enhance the metadata to implement a list-of-values UI using the Department business object as an example. In the next step (Add a LOV with a Field Template and Validation), we show an alternative implementation that uses the Job business object.

  1. Click the Source tab and locate and open the data-description-overlay.json file under the dynamicLayouts/Employee node.
  2. Under the replaceMetadata entry in the open file, add the following definition to replace the metadata definition of the department property. Use the oj-select-single component to render the list of values: Expand to view code 
    "replaceMetadata": {
  "$common": {
    "department": {
      "labelHint": "Department",
      "componentType": "oj-select-single",
      "dataProvider": {
        "factory": "vb/types/factories/serviceDataProviderFactory",
        "parameters": [
          {
            "dataProviderOptions": {
              "endpoint": "businessObjects/getall_Department",
              "uriParameters": {
                "onlyData": "[[true]]"
              },
              "keyAttributes": "id",
              "itemsPath": "items"
            }
          }
        ]
      },
      "optionsKeys": {
        "value": "id",
        "label": "departmentName"
      }
    }
  }
}

    The Dynamic UI now generates a list-of-value component wherever the employee's Department field is rendered.

Add a LOV with a Field Template and Validation

Another way to add a list of values is to use a field template. We use this technique on the job property and store the selected row values for advanced data validation.

  1. Click the Layouts tab and open the default layout view of the Employee layout's Add Row Form for editable table rule set.
  2. In the Variables tab, add the following variables:
    • jobListSDP of type ServiceDataProvider that references the getall_Job endpoint.
    • minSalary of type Number that holds the value for the mininimum salary for the selected job.
    • maxSalary of type Number that holds the value for the maximum salary for the selected job.
  3. In the Templates tab, create a new field template named jobSingleSelect.
  4. In the template definition for jobSingleSelect, replace the component code with oj-select-single and set the data attribute value to jobListSDP. Also add a value item change listener to oj-select-single: 
    <template id="jobSingleSelect">
  <oj-select-single label-hint="[[ $labelHint ]]" value="{{ $value }}" data="[[ $variables.jobListSDP ]]" item-text="jobTitle"
    on-value-item-changed="[[$listeners.selectValueItem]]"></oj-select-single>
</template>
  5. In the change listener's action chain, modify the values of the minSalary and maxSalary variables from the selected job row.
  6. Finally, for the salary field, add a field template salaryWithRangeValidation and set the min and max attribute values for the Input Number field to the variables shown below: 
    <template id="salaryWithRangeValidation">
  <oj-input-number value="{{ $value }}" label-hint="[[ $labelHint ]]" min="[[ $variables.minSalary ]]"
    max="[[ $variables.maxSalary ]]"
    converter='{"options":{"style":"currency","currency":"USD","currencyDisplay":"code"},"type":"number"}'></oj-input-number>
</template>

    Similarly, you can set a field template for the Edit Row Form for editable table rule set.

Track and Save Changes

Saving changes involves collecting them from the Buffering Data Provider instance, creating a single batch REST Call payload to store all changes in one transaction.

  1. In the Component Palette, drag a Button component and drop it on the Page Designer above the Dynamic Table component. In the General tab of the Properties pane, set the Text property to Save.
  2. In the Events tab of the Properties pane for the Save button, add a Quick Start: 'ojAction' event and a corresponding JS action chain named saveActionChain.
  3. In the saveActionChain action chain, add a Call Function action named createBatchPayload. This function creates a payload of the changes to upload and uses the getSubmittableItems() function of the Buffering Data Provider which contains the changes (add, update, and delete). Expand to view code 
        /**
     * @param {Object} context
     */
    async createBatchPayload(context) {
      const { $page, $flow, $application } = context;
      const generateBatchSnippet = function (url, payload, operation, id) {
        return {
          id: id ? id : "someID",
          path: url,
          operation: operation,
          payload: payload ? payload : {},
        };
      };
      let payloads = [];
      let uniqueId = new Date().getTime();
      let editItems = $page.variables.employeesCustomBDP.instance.getSubmittableItems();
      editItems.forEach((editItem) => {
        let change = editItem.operation;
        let key = editItem.item.metadata.key;
        // clone record - some properties will be deleted from the clone:
        let record = JSON.parse(JSON.stringify(editItem.item.data));
        if (change === "remove") {
          payloads.push(
            generateBatchSnippet("/Employee/" + key, {}, "delete")
          );
        } else if (change === "add") {
          //delete record.departmentObject;
          //delete record.jobObject;
          //delete record.id;
          // default some required fields:
          // record.email = 'person' + (++uniqueId) + '@company.com';
          record.hireDate = new Date();
          record.department = 1;
          record.job = 1;
          payloads.push(
            generateBatchSnippet("/Employee", record, "create")
          );
        } else if (change === "update") {
          delete record.departmentObject;
          delete record.jobObject;
          payloads.push(
            generateBatchSnippet(
              "/Employee/" + key,
              record,
              "update"
            )
          );
        }
      });
      return {
        parts: payloads,
      };
    }
  4. Add a Call REST action to upload the payload through the business objects Batch REST endpoint. The Batch REST endpoint sends multiple changes in one transaction.
  5. On the success outcome of the REST Call action, reset the status of the records using resetAllUnsubmittedItems() and fire a notification with the message that Changes are saved. On the failure path of the REST Call action, fire a notification with the failure message as seen in the code example below. Expand to view code 
        async run(context) {
      const { $page, $flow, $application } = context;

      // create a batch payload for the unsubmitted items
      const batchRESTPayload = await this.createBatchPayload(context);

      // check if there is any modified/added data available
      if (batchRESTPayload.parts.length === 0) {
        await Actions.fireNotificationEvent(context, {
          displayMode: 'transient',
          type: 'info',
          summary: 'Nothing to save.',
        });
      }
      else {
        // call the batch rest call
        const batchPostResult = await Actions.callRest(context, {
          endpoint: 'businessObjects/batch',
          body: batchRESTPayload,
        });

        if (batchPostResult.status === 200) {
          $page.variables.employeesCustomBDP.instance.resetAllUnsubmittedItems();

          await Actions.fireNotificationEvent(context, {
            summary: 'Changes are saved.',
            displayMode: 'transient',
            type: 'confirmation',
          });
        } else {
          await Actions.fireNotificationEvent(context, {
            displayMode: 'persist',
            type: 'error',
            summary: ' Save failed. Error: ' + batchPostResult.statusText,
          });
        }
      }
    }
