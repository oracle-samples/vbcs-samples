Add a Table to the page and add data using the Employee endpoint to the table.

Implement default sorting in the table

  1. Define the default sort for the table by creating a page variable sort of type Object with two fields:
    • attribute with default value as firstName
    • direction with default value as descending
    Set the persistence of the variable to Device if sort criteria needs to be stored across sessions or History if sorting should be preserved only when drilling into child page and coming back.
  2. Set the sortCriteria parameter of the table's Service Data Provider variable (employeeListSDP in this example) to the sort page variable created in Step 1. The sortCriteria is of type array, allowing sorting by multiple attributes such as firstName, lastName, email. The sort variable is an object which during assignment is converted into an array of objects.
    3. Note:

    If your SDP uses a customized fetch chain, the name of the parameter is not sortCriteria but requestTransformOptions.sort.

    The firstName column of the table is now sorted in descending order.

Preserve sorting in the table

  1. The table needs to fire an event called ojSort when sorting is applied on the columns. Add this event to the table component which fires an action chain TableSortChain. 
     "ojTableSort": {
      "chains": [
        {
          "chain": "TableSortChain",
          "parameters": {
            "sort": "[[ $event.detail ]]"
          }
        }
      ]
  }
  2. In the TableSortChain action chain, add { sort } parameter into chain's run function: 
    async run(context, { sort }) {
     and set the value of sort variable to: 
    {
  attribute: sort.header,
  direction: sort.direction,
}
