When multiple dynamic forms share editing of a single entity record, as in the case of the Advanced Create and Edit Page Template that composes a UI of focused sections, the quick-start generated code results in one REST call per dynamic form.

We use the dynamic UI's $metadata.provider.getFieldsToFetch API and then edit the page to make one REST call for the dynamic forms in the page that edit the record. The getFieldsToFetch returns the configuration of the fields which are needed to render the layout(s) based on the layout and metadata. We pass getFieldsToFetch all three layouts and it returns a union of fields to fetch if all layouts are for the same entity record.

Update Page to Make One REST Call

  1. In the Code view of the Page Designer, remove the rendered-fields property from all the forms and, in the Event Listeners and Variables tabs, also remove the variables and listeners used for this property.
  2. In the Event Listeners tab, use one of the loadEmployeeChain action chains from the vbEnter page event listener to fetch data during page opening and delete the other two redundant loadEmployeeChain action chains.
  3. In the loadEmployeeChain action chain, remove the fetchedFields parameter from the action chain and replace it with the $metadata input parameter instead. In the vbEnter listener, map $metadata.businessObjectsUpdateEmployeeMetadata as a value for the $metadata chain parameter.
  4. Still in the action chain, add the following line after the Reset Variables block to combine all the fields from multiple dynamic form layouts into one constant: 
    const fetchedFields = await $metadata.provider.getFieldsToFetch({layout:["nameSection", "salaryForm", "contactForm"]});
    Note that the fetchedFields variable is later passed into Actions.callRest through the responseFields parameter to tell the REST call which fields to fetch.
