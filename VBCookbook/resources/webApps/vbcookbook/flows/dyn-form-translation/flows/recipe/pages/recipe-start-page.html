Add a Dynamic Form and use the Configure as Edit Form quick start to display employee details.

Import Translation Bundle

Before you can use the Property Inspector to reference UI strings from the translation bundle, you need to import the translation bundle into the data-description-overlay.json and layout.json files by adding the following entry to each file:

"translations": {
  "app": {
    "path": "resources/strings/app/nls/app-strings"
  }
}

To access the data-description-overlay.json file, use the Source tab and expand dynamicLayouts and the appropriate layout (Employee in our example). You can access the layout.json file from the JSON tab in the Layouts tab.

After you import the translation bundle, you can use the Property Inspector to translate dynamic UI elements. You can view the following examples in this recipe. The following UI references assume that you selected English as the language (First Name, Review Needed? and Contact Details)

  • Field Template

    Components inside a custom field template can be translated. See the label-hint for First Name. 

    <template id="firstNameTranslation">
  <oj-input-text value="{{ $value }}" 
    label-hint="[[ $translations.app.key_firstname ]]"></oj-input-text>
</template>

  • Entity fields can have label hints translated. See Review Needed?

    "review": {
  "labelHint": "[[ $translations.app.key_review]]"
},

  • Layout sections can have translated labels. See the Contact Details section.

    "Contact Details": {
  "description": "",
  "layout": {
  "labelHint": "[[ $translations.app.key_contactdetails ]]",
  "displayProperties": [
  "phoneNumber",
  "email"
  ]
 }
